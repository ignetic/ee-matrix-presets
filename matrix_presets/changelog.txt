Changelog for Matrix Presets
===============================


## 2.0.1

- Fixed rows deleted from the Matrix (before the entry is saved) being included when saving a preset

## 2.0.0

Requires ExpressionEngine 7. Use 1.3.8 for EE2-EE6.
Run the add-on update in the CP (Add-ons) to convert existing presets.

- Presets are saved as JSON in a larger (MEDIUMTEXT) column: no more PHP max_input_vars or 64 KB limits
- Existing presets are converted to JSON by the update
- Rows are added through Matrix's own API, and loading stops at the field's maximum rows
- Saving checks the field is a Matrix field
- Members without access to the add-on no longer get errors (the buttons are just not shown)
- Loading no longer triggers a burst of EE form validation requests (validation is paused while rows are filled)
- Wygwam content is set in the cell's editor instead of re-creating it (deferred editors show it in their preview)
- MX Select Plus (Chosen) and multi-selects show the loaded values; missing options are added, for multi-selects too
- Chosen's search box is no longer saved in presets
- Save selects the new preset, and asks for rows when the Matrix is empty
- Ready for jQuery 4 (no positional selectors)
- Removed: EE2-EE6 support and the pre-1.2 settings migration (update to 1.3.8 first to keep presets from 1.1 or earlier)

## 1.3.8
-- Fixed Playa (drop panes) selections not loading; presets now only store selected entries (presets saved before 1.3.8 leave Playa unchanged)
-- Fixed rows being miscounted when a cell contains its own table (e.g. Playa), which could load rows into the wrong place
-- Fixed Matrix rich text (RTE) columns loading empty on EE6+ (the content is now set in the RedactorX/Redactor/CKEditor editor)

## 1.3.7
-- Fixed new presets overwriting preset 10 once a field had 10 or more presets
-- Fixed presets loading into the wrong columns after Matrix columns were added or reordered (new presets are saved by column ID; older presets still load by column position)
-- Fixed checkboxes and radios not saving or loading their checked state (presets saved before 1.3.7 leave them unchanged)
-- Fixed select values containing quotes breaking the load, and missing options being added with the wrong value
-- Fixed empty presets being saved when the Matrix has no rows
-- Fixed Assets files not loading (files are now added through the Assets field, with their thumbnails, and can be removed/reordered)
-- Fixed Channel Images Select images not loading (the picker is rebuilt with the loaded images)
-- Fixed JS errors when loading a missing preset, or an Assets column when Assets isn't loaded
-- Security: preset names and loaded values are escaped (preset names could inject HTML into the CP)
-- Security: stored presets are unserialized as arrays only (PHP 7+)
-- Performance: presets are only requested on publish pages with Matrix fields
